# ORNG LED CONTROL — Hardware Day Checklist

Статус: **PENDING HARDWARE**  
Цель первого аппаратного дня: подключить Windows-ноутбук к Art-Net-контроллеру,
точно определить реальные каналы приборов, зафиксировать patch и откалибровать
сцену без догадок.

Этот checklist относится к ноутбучному этапу. Raspberry Pi и GPIO выполняются
позже отдельным этапом.

## 1. Правила фиксации результата

Для каждого пункта используется один статус:

- `PENDING`;
- `IN PROGRESS`;
- `PASS`;
- `FAIL`;
- `BLOCKED`;
- `NOT APPLICABLE`.

`PASS` ставится только после реального наблюдения. Скриншот Mock, unit test или
видимый UDP-пакет на ноутбуке не подтверждает физическую работу прибора.

Для каждого важного наблюдения записать:

- дата и время;
- прибор и его физическая позиция;
- выбранный mode на дисплее прибора;
- стартовый адрес;
- локальный канал;
- проверенные значения/range;
- видимый результат;
- файл конфигурации/профиля, который изменён;
- commit hash после фиксации.

## 2. Что взять и подготовить

- Windows-ноутбук с актуальным `main`;
- USB-C → Ethernet переходник;
- Ethernet-кабель к Art-Net-контроллеру;
- Art-Net-контроллер и его питание;
- DMX-кабель к первому прибору;
- доступ к дисплеям/кнопкам приборов;
- возможность обесточить отдельный прибор;
- установленное приложение ORNG LED CONTROL;
- резервная копия provisional YAML;
- checklist, открытый для записи фактов.

Желательно тестировать по одному типу приборов и не включать всю сцену до
проверки Blackout.

## 3. Безопасность перед первым output

- [ ] Beam направлены в безопасную область, не в глаза людей и не в отражающие
  поверхности.
- [ ] Перед неизвестными Beam-каналами рядом нет людей.
- [ ] Master brightness установлен на минимальное безопасное значение.
- [ ] Mock является активным transport при старте.
- [ ] UI Blackout доступен и проверен в Mock.
- [ ] Raw tester показывает все нули.
- [ ] Strobe не удерживается.
- [ ] Для первого теста подключён один контролируемый прибор.
- [ ] Не выполнять слепой sweep `0 → 255` по неизвестным каналам: канал может
  оказаться reset, macro, shutter или быстрым движением.

## 5. H002 — Blackout и поведение контроллера

Статус: `PENDING`

1. Отправить нулевой кадр.
2. Поднять один заведомо безопасный dimmer-канал на малое значение.
3. Нажать Blackout.
4. Проверить фактическое выключение.
5. Выключить output из UI.
6. Закрыть приложение штатно.
7. Разорвать Ethernet на тестовом слабом уровне света.
8. Зафиксировать, удерживает ли контроллер последний кадр и есть ли собственный
   timeout/blackout.

Acceptance:

- Blackout физически работает;
- raw test не остаётся активным после выхода;
- shutdown zero-frame проверен;
- поведение при потере сети задокументировано;
- если контроллер держит последний кадр, это отражено в safety design, а не
  скрыто.
